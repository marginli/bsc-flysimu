1這些影片是什麼

三段影片都是種子 0 的第 0 局，分別用完整接線（fly）、損毀 AOTU025（lesion025）、打亂接線並各自校準（scrambled_cal）三種大腦玩。擊殺數分別是 7、2、0，和 PART 3 第 7 節表上第 0 局的數字相同——影片就是重現時實際跑出來的那一局。

錄影時同時記下每一格（1/35 秒）的四組神經元放電率（左右各一，共 8 組）、遊戲回報的敵人方位、以及按了哪些鍵。網頁播放時只是重播這些紀錄，不會在瀏覽器裡重新模擬：神經元模型與遊戲引擎都是 Python 套件，瀏覽器跑不了。

擊殺數 7、2、0 與第 0 局的對照：out/fruitfly/local_doom_vizdoom130/ 各條件 JSON 的 episodes[0]。

3三種大腦並排

同一個種子、同一張地圖、同一套讀出規則，只差在大腦。按一次播放，三局一起開始，各自打到玩家死亡為止。

4在畫面上找三件事

用播放台的 ¼× 慢放或逐格前進，在「完整接線」那一局找：

  1. 敵人從左邊出現時，視野條上出現藍點，LC10a 左先亮、接著 AOTU019 左亮，轉向訊號往左超過閾值，按「左轉」。這是 PART 1 第 4 節的讀出規則在運作。
  2. 敵人轉到正中間時，兩側 AOTU019 一起亮、開火條件的長條越過紅線，按「開火」；這時看迴路圖最下面，兩顆 DNa02 都是 0。這就是 PART 5 第 4 節的發現：正前方的瞄準與開火完全不經過下行神經元。
  3. 敵人出現在畫面邊緣時（大約第 4.2 秒，從右側 +83° 出現），AOTU025 右與 DNa02 右才亮起來。切到「損毀 AOTU025」那一局，這條路是暗的（迴路圖上打紅叉），所以邊緣的敵人比較難被轉回中央——這就是它 50 局平均只有 4.92 的原因（PART 5 第 2 節）。

再切到「打亂接線」那一局：迴路圖上的連線已經不代表這個大腦（打亂後的接線畫不出來，圖上保留原本的接線並調淡），放電的模式與敵人的位置對不起來。

第 4.2 秒、+83° 的敵人：assets/demo/data.json 裡 episodes.fly 第 146 格的 e（out/demo_data.json 同一份）。
