1三個指令

下載 flysimu-code.zip，解壓縮到一個空資料夾，在那個資料夾裡開終端機，依序執行：

bash setup_envs.sh              # 建四個 conda 環境（只需一次）
bash fruitfly_lab/run_all.sh    # fruitfly-lab：FF1–FF6、ViZDoom 1.3.2 對照、加做檢查 E1–E4
bash blackjack/run_all.sh       # fly-blackjack：BJ1–BJ5、加做檢查 X1–X4

本課在一台 Linux、12 核 CPU 的電腦上，從解壓縮開始實測：建四個環境 54 秒，fruitfly-lab 14 分 34 秒，fly-blackjack 21 分 54 秒（兩個同時跑）。建環境那一項是在沒有同名環境的情況下另外實測的，而且這台電腦已經有套件的下載快取；在新電腦上第一次建，會因為要下載套件而更久。兩個 run_all.sh 互不相干，可以同時開兩個終端機各跑一個。

實測時間出自 out/porttest.json（下載包解到空資料夾後的完整執行紀錄）。

項目說明
作業系統Linux 或 macOS。fruitfly-lab 的作者在 macOS 上跑、本課在 Linux 上跑，兩邊逐局相同（PART 3 第 7 節）

GPU不需要

硬碟用量出自 out/porttest.json。

3下載包裡有什麼

下載包只有本課自己寫的程式。兩個被重現的專案由 run_all.sh 從 GitHub 取得，並切換到固定的版本——fruitfly-lab 沒有授權檔，所以它的任何檔案都不能由本課散布（首頁〈出處〉）。

檔案做什麼
setup_envs.sh建四個 conda 環境，套件版本照本課實跑時固定
fruitfly_lab/run_all.sh取得 fruitfly-lab 與 Shiu 的全腦模型、下載 FlyWire 註解檔，依序跑 FF1–FF6、ViZDoom 1.3.2 對照、E1–E4。另外下載了 FlyWire 官方的連線表 proofread_connections_783.feather 的話，先設 FLYWIRE_FEATHER=<檔案路徑> 再跑，FF1 會逐條比對（PART 3 第 3 節）
fruitfly_lab/ext/FF1 的資料核對與 E1–E4 的程式。只匯入作者的程式，不修改它
blackjack/run_all.sh取得 fly-blackjack、下載 MaleCNS 預處理矩陣，依序跑 BJ1–BJ5、X1–X4
blackjack/scripts/作者沒有命令列入口的兩個實驗（覓食、21 點）的呼叫程式，以及 X1–X4
check.py、expected.json驗收：逐項比對你跑出來的數字與本課實跑的結果（第 7 節）
SHA256SUMS.txt每個檔案的 SHA-256 指紋，用 sha256sum -c SHA256SUMS.txt 確認下載的檔案沒有損壞

兩個 repo 的版本與下載來源寫在下載包的 fruitfly_lab/run_all.sh、blackjack/run_all.sh。

4四個環境

兩個專案需要的套件版本互相衝突，所以分成四個環境。setup_envs.sh 一次建好：

環境名稱Python關鍵套件給誰用
flyplay_bj3.11numpy 2.4.6、scipy 1.17.1、pandas 3.0.6fly-blackjack 全部
ffl_brian3.11Brian2 2.9.0、numpy 1.26.4、pyarrow 17.0.0fruitfly-lab 的抽子圖、全腦模型（FF1–FF3、E4）
ffl_doom1303.12vizdoom 1.3.0、numba 0.68.0fruitfly-lab 的遊戲（FF4–FF6、E1–E3），與作者相同的版本

Python 版本出自 out/porttest.json 的 python_versions；完整套件清單在 out/blackjack/env.txt 與 out/fruitfly/env_brian.txt、env_doom130.txt、env_doom.txt。

5三個要固定版本的地方

一、程式碼：固定到某一個 commit

GitHub 上的專案會一直更新。commit 是專案每一次存檔的版本編號；run_all.sh 取得程式碼之後會切到本課用的那一版（fruitfly-lab 8c27fe8、fly-blackjack 004b2e3）。作者日後改了程式，你跑出來的仍然是本課的那一版。Shiu 的全腦模型 repo 取最新版，因為 fruitfly-lab 只讀它附的連線表，而那份連線表在 FF1 會逐條核對。

二、遊戲引擎：ViZDoom 1.3.0

不指定版本的 pip install vizdoom 會裝到 1.3.2。兩個版本只差一個小版號，但遊戲本身的隨機抽樣不同，同一組種子下每一局的分數都會變，連不使用神經網路的條件也一樣（PART 3 第 8 節）。所以主要的環境固定在作者用的 1.3.0，另開一個 1.3.2 的環境只做對照。

三、Brian2、numpy 與 pyarrow 的版本衝突

Shiu 的全腦模型用 Brian2 2.9，它需要 numpy 2 以前的版本；而讀連線表要用的 pyarrow 從 18 版開始需要 numpy 2 以後的版本。兩者同時裝最新版會衝突，所以 ffl_brian 把 pyarrow 固定在 17。fruitfly-lab 的 README 用另一個安裝工具 uv、只註明「Brian2 2.9 需要 numpy 2 以前的版本」；本課用 pip 照同一份套件清單安裝時遇到這個衝突。

衝突的說明記在 out/fruitfly/env_notes.txt。

6一個會讓結果悄悄改變的陷阱

如果你曾經用 pip install --user 裝過套件，它們會被放在家目錄的 ~/.local 底下；而 Python 預設會把這個資料夾也加進搜尋範圍——包括 conda 環境裡同一個版本的 Python。結果是：你以為在用環境裡固定好的 numpy 2.4.6，實際上載入的可能是 ~/.local 裡的另一個版本，而且不會有任何警告。

下載包的每一支腳本都先設定 PYTHONNOUSERSITE=1，讓 Python 不去讀 ~/.local。自己在終端機裡手動執行單一步驟時，也要在指令前面加上它：

PYTHONNOUSERSITE=1 $(conda info --base)/envs/ffl_doom130/bin/python doom/fly_doom.py --policy fly --episodes 1

numpy 2.4.6 是 flyplay_bj 環境固定的版本（out/blackjack/env.txt）。

7跑完之後怎麼看

每個 run_all.sh 跑完都會自動執行 check.py，逐項比對你的結果與本課實跑的結果，每一項印一行：

符號意思
✓對上了。判定標準依那一項而定：逐位相同，或全腦模型那幾項在 ±20% 內（三種判定標準見 PART 3 第 1 節）
✗對不上。後面會印出本次的值與預期的值
△本課實跑時也對不上、頁面上已經說明的項目（目前只有一項，見 PART 3 第 5 節），不算失敗

本課的可攜測試（解到空資料夾、從建環境開始跑）最後兩行是：

fruitfly：45 項通過，0 項不符，1 項已知不符（△，本課實跑時也一樣）（共 46 項）
blackjack：19 項通過，0 項不符（共 19 項）

出自 out/porttest.json。

想看某一步的細節，打開那個資料夾裡的 logs/：每一步一個檔案，是那一步的完整終端輸出，最後幾行通常就是結果表。所有數字另外以 JSON 存在 results/，PART 3 到 PART 5 的每一張表都標了它對應哪一個檔案。
