1結論：五個步驟的成績

判定標準有三種——逐位相同、在誤差範圍內、形狀相同——定義見 PART 3 第 1 節。fly-blackjack 的每個實驗都固定了亂數種子（程式每次抽到的隨機數都一樣），所以同一份程式在另一台電腦上跑，應該得到一模一樣的數字；本課事先訂的標準就是：作者附的結果要逐位相同，比到 README 寫出的位數（README 寫 −1.30，本機算出 −1.301，算相同）。

兩類步驟事先訂得寬一些。需要重新訓練讀出的步驟（CEM 訓練，見 PART 1 第 6 節）：訓練要跑幾萬局遊戲、牽涉大量浮點運算與好幾個套件，事先不敢保證另一台電腦會算出一模一樣的數字，所以只要求形狀相同——學習組明顯好過對照組。實跑結果比標準好：CEM 的種子是寫死在程式裡的，BJ1 和 BJ4 的 C 組重新訓練出來的數字都與作者逐位相同；BJ4 的 B 組對不上，是因為訓練參數不同，不是隨機性（第 5 節）。21 點的勝率（BJ5）：作者只在程式註解裡給了取整數的百分比，所以比的是「有多巴胺那組升到作者寫的水準、對照組不動」，也屬形狀相同。

3BJ2　切出蕈狀體：md5 相同，README 的兩個連結數對不上

BJ2 驗的是「切出蕈狀體」這一步能不能一模一樣地重做。作者的 flybrain.mb.fetch 從 connectome_data_prep（另一位研究者 Yijie Yin 在 GitHub 上公開的整理版，把 MaleCNS 連結體存成可以直接讀的表格；下載時指定了固定的檔案版本）下載連結矩陣（哪顆神經元連到哪顆、幾個突觸），flybrain.mb.extract 從裡面切出 PART 1 第 6 節表裡的四群神經元（PN、KC、MBON、DAN），存成一個檔 data/mb_circuit.npz。README 宣稱這個切法在任何電腦上都逐位相同（同一支程式跑兩次應得到相同的 md5），但作者沒有附上他自己算出的 md5 值。所以能驗的是兩層：第一層照作者說的跑兩次、比兩次是否相同；第二層把切出來的細胞數與連結數對回作者存進 repo 的紀錄檔。比檔案不必逐條比對幾萬條連結，比 md5 就夠了：md5 是從整個檔案算出來的一串指紋，內容只要差一個位元，指紋就完全不同。本課跑兩次、比兩次的 md5：

32dc49359f237250162ed33dcb5da93c  data/mb_circuit.npz
32dc49359f237250162ed33dcb5da93c  data/mb_circuit.npz

兩次相同（第一層過）。這只證明同一台電腦兩次一樣；跨電腦的證據在下一張表。輸出在 out/blackjack/logs/bj2_md5.txt。

4BJ3　制約學習：學習指數相同

BJ3 驗的是 PART 1 第 6 節的學習規則在作者的設定下，算出來的學習指數是否與 README 相同。做法：隨機挑兩種氣味 A、B——模型裡一種氣味就是觸角葉裡 8 個小球區（glomerulus）的投射神經元一起活化，哪 8 個由氣味的名字決定，所以 A、B 各活化一組不同的 KC。A 出現時同時「電擊」——讓懲罰群多巴胺神經元（PPL1）放出多巴胺——B 出現時不電；重複 20 次。換 12 個亂數種子（每個種子抽到的氣味與隨機數不同）各做一遍，取平均。

兩個指數：學習指數＝ A 的好惡值改變量 − B 的改變量，愈負代表愈怕 A，模型完全沒變就是 0。T-maze 位移＝訓練後的偏好指數 − 訓練前的；偏好指數是讓 100 隻模擬果蠅在 A、B 之間選邊：這 100 隻用的是同一個蕈狀體，每一隻選 A 的機率由「A 的好惡值減 B 的好惡值」決定（差愈大機率愈偏，差 0 時各半），再各抽一次；(選 B 的隻數 − 選 A 的隻數) ÷ 100，全部選 B 是 +1，各選一半是 0。

五個條件：連結體＋可塑性是完整模型；關掉可塑性把學習率設 0；切斷多巴胺把 DAN→MBON 的連結全部設 0，多巴胺送不到 MBON；氣味與電擊不同時出現照樣電擊，但只在 A 不在場時電；KC→MBON 打亂把這層連結隨機重排（PART 5 的 X2、X3 會再談它為什麼還能學）。前三個對照照理都該學不到東西：

5BJ4　覓食：README 少寫了一個參數

覓食是 PART 1 第 6 節的實驗：果蠅在場地裡走，兩個氣味源一個有食物、一個會電擊，蕈狀體在這一場裡自己學哪個危險。它分兩段：控制移動的讀出先用 CEM 訓練好——這個讀出的輸入是 8 個數（腳下氣味多濃、左右觸角哪邊濃、最近的氣味源在哪個方向、自己的速度，以及蕈狀體給的好惡值），輸出是下一步怎麼走；作者把訓練好的參數存在 policies/forage.json（本頁叫它策略檔）；再用這組參數讓果蠅跑 40 場、每場 90 秒（40 個種子＝ 40 種不同的起始位置與氣味源位置），算平均每場被電擊幾次。被電得愈少，代表愈快學會躲開電擊那個氣味；另外也記每場吃到幾次食物，看它有沒有在找氣味源。三個條件與 BJ3 相同：學習（完整模型）、切斷多巴胺、關掉可塑性。

判定分兩層：拿作者附的策略檔直接跑，要逐位相同；自己重新訓練讀出，事先只要求形狀相同——學習組被電的次數明顯少於兩個對照組（理由見第 1 節）。

A 組：學習組每場被電 3.85 次、切斷多巴胺與關掉可塑性都是 7.50 次，吃到食物 5.475／5.25／5.25 次，與 README 逐位相同，第一層過了（兩個對照組數字一模一樣，是因為多巴胺送不到和學習率為 0 對模型的效果相同——連結都不會變——又用同一串亂數）。B 組的問題不只是數字不同：學習組被電 1.93 次、切斷多巴胺 1.88 次，學習沒有帶來任何好處，形狀就不對了。再看食物就知道為什麼：B 組每場只吃到約 1.3 次（1.275／1.25／1.25；作者約 5.5 次），也就是這個重新訓練出來的讀出幾乎不去找氣味源；果蠅不靠近氣味源，就不會被電、也不會吃到食物，蕈狀體學到什麼都派不上用場。問題出在讀出訓練，不在蕈狀體。

原因寫在作者自己的策略檔裡。policies/forage.json 除了訓練好的參數，還記錄了訓練時的設定（seed 是訓練用的亂數種子，seconds 是訓練時每一回合跑多久，validation 是訓練結束時在 4 個驗證場地的平均分數——吃到食物加分、被電扣分、閒著不動也每秒扣分）：

{
 "task": "forage",
 "seed": 20260913,
 "seconds": 45.0,
 "validation": 2942.240450387357
}

策略檔裡除了參數本身以外的欄位，收在 out/upstream/blackjack_forage_policy_meta.json。

作者訓練時每一回合是 45 秒；而 README 第 308 行教讀者打的指令 train(generations=32) 沒有指定這個參數，程式就用內建的預設值 40 秒。回合短 5 秒，訓練出來的讀出就不一樣——CEM 挑的是在那個回合長度下分數最高的參數，回合長度變了，被挑中的參數也變了。把指令改成 train(generations=32, seconds=45.0) 重新訓練：訓練的驗證分數是 2942.24，和策略檔記錄的值一樣；三個條件的電擊與食物數也都與作者逐位相同（C 組）。

已找到原因：README 第 308 行的訓練指令少寫了 seconds=45.0。下載包的 blackjack/scripts/bj4b_forage_s45.py 補上這個參數，重新訓練的結果與作者附的策略逐位相同。bj4_forage.py 保留照 README 原樣的訓練，作為對照。

6BJ5　21 點：勝率對上，學到的策略對不上

21 點是 PART 1 第 6 節的第三個任務。模型怎麼打：每一手，把「自己的點數、手裡的 A 算不算 11 點（軟手）、莊家的明牌」連同候選的動作一起編成一組像氣味一樣的 KC 活化——同一手牌配「要牌」「停牌」「加倍」是三種不同的「氣味」，所以每個動作各有一個好惡值——選最高的；一手結束，贏了給獎賞多巴胺、輸了給懲罰多巴胺，這一手做過的每個決定都依 PART 1 第 6 節的學習規則更新連結。作者在 flybrain/mb/blackjack.py 的檔尾用註解寫了實驗設定：3 個種子、每個 30,000 手、對照組先跑。勝率在這裡指平均每手的淨輸贏（以一注為單位、寫成百分比：−15% 就是平均每手輸 0.15 注），取最後 2,000 手。表裡的「探索」是模型每一手有一定比例不看好惡值、隨機亂選動作，這個比例從 35% 隨手數遞減到 3%。兩個對照組的曲線是平的，而且它們也照同樣的時程把亂選比例降下來；曲線還是平，表示「亂選」和「照沒學過的好惡值選」輸得差不多（都在 −45% 上下），亂選變少看不出差別。這同時說明有多巴胺那組的上升不是亂選變少造成的。

作者的值出自 blackjack.py 檔尾註解（收在 out/upstream/blackjack_py_RESULT_comment.txt）；本機在 out/blackjack/bj5_blackjack_30000.json。「關掉學習」與「切斷多巴胺」三個種子的數字一模一樣，原因和 BJ4 相同：多巴胺送不到 MBON 時連結一樣不會變，兩種對照對模型的效果相同，又用同一串亂數抽牌與抽探索，打出來的每一手都一樣。本機三個種子彼此差到 7 個百分點，表示單一種子的勝率本來就有這麼大的浮動，所以這一步比的是三種子平均與形狀，不是逐位。

勝率的改善重現了，而且只出現在有多巴胺的那一組。不過圖 2 也看得出，學會的那條只爬到「永遠停牌」參考線附近——成績和一個永遠不要牌的玩家差不多。所以作者接著宣稱的「它學到什麼策略」才重要：基本策略是賭場數學算出來、公開的一張表，寫明每種情況該怎麼打；把莊家每一種明牌（2 到 A，10 種）× 自己每一種可能的手牌（硬手 5 到 21 點 17 種、軟手 13 到 21 點 9 種，共 26 種）排成 260 格，看模型在每一格選的動作有幾格與這張表相同，就是一致率。作者還附了一個訓練完的蕈狀體狀態檔 data/brain_seed.json（下面叫它大腦檔）。這一部分，作者自己留下的三份資料就互相矛盾：

先說表裡兩個 52%：同一個大腦檔，檔內記錄 53.1%（138 格）是作者網頁版自己算的，載入 Python 重算是 51.9%（135 格），兩套評分程式對同一份連結強度算出的格數差 3 格，原因本課沒有追。作者附的大腦一致率約 52%，和 README 相符，但它要牌 97 格，不是註解說的「幾乎全部停牌」；大腦檔標明是種子 0，本機用同一份程式、同一個種子重跑，又是第三種結果。勝率能重現、策略卻不同，並不矛盾：學會的勝率只到「永遠停牌」那條線，很多張不同的 260 格表都能打出差不多的勝率，勝率對上不代表每一格的選擇相同。所以這一步的結論要分開講：「有多巴胺才會變好」可以重現；「學到什麼策略、一致率多少」從公開的程式碼重現不出來。最直接的解釋是附的大腦檔由另一個版本或另一組設定的程式產生，但作者沒有記錄，本課無法確認。

這一頁帶走的事：README 是作者對結果的摘要，不是結果本身。這一頁兩處對不上，真正的資訊都在 repo 的其他檔案裡——策略檔記錄的訓練長度、manifest 記錄的連結數、大腦檔記錄的一致率。重現時遇到對不上，先找作者留下的輸出檔，再回頭判斷 README 寫的是哪一個版本。
